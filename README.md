# 引っ越し費用まとめ帳

## 1. サービス概要

引っ越しを検討している人が、物件契約や引っ越し準備にかかる費用を入力し、まとめて保存・管理できるサービスです。

引っ越しでは、敷金・礼金・仲介手数料・前家賃・引っ越し業者費用・家具家電費用など、複数の出費が同時に発生します。本サービスでは、それらを4つのカテゴリに分けて管理し、総額・内訳・予算との差を確認できます。

各費用には「未確認・概算・確定」の状態を設定でき、金額が分からない段階から整理を始められます。会員登録なしで費用計算を試せるほか、会員登録後は複数の費用リストを保存し、2件を比較できます。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

引っ越しについて調べたときに、具体的な料金を知ろうとすると、早い段階で氏名・電話番号・住所などの個人情報入力を求められる場面が多いことに違和感がありました。

まだ依頼するか決めていない段階では、「まずはだいたいどのくらいかかるのかだけ知りたい」と思っていても、気軽に確認しづらいと感じました。費用感が分からないまま比較検討を進めることへの不安が、このアイデアのきっかけです。

### 2-2. なぜそれが気になったのか

私は、何かを決める前に全体感や目安を把握し、納得してから次の行動に進みたいと考えることが多いためです。

引っ越しは条件によって費用が変わり、業者費用以外にも出費が重なります。見積もり依頼や物件契約の前に、自分のペースで費用を整理できるサービスを作りたいと考えました。

---

## 3. 解決したい課題

**引っ越し業者費用や賃貸初期費用を含めた総額を把握しづらく、予算計画を立てにくいこと**です。

具体的には、次の困りごとを想定しています。

- 賃貸初期費用・引っ越し業者費用・家具家電費用などの情報が分散している
- 金額が分からない項目と、仮の金額・確認済みの金額を区別しづらい
- 自分の予算に対して、いくら余裕があるか、いくら足りないか分かりにくい
- 検討している物件や引っ越し条件ごとの費用を比較しづらい

入力した金額を一括で集計し、費用の状態を管理しながら更新できるようにすることで、予算判断を支援します。

---

## 4. 想定ユーザーと利用の流れ

### 4-1. 想定しているユーザー

- 進学・就職・転職・一人暮らし開始・住み替えなどで、近いうちに引っ越しを検討している20代〜30代
- 業者への見積もり依頼や物件契約の前に、まず費用感を整理したい人
- メモやスプレッドシートを自分で作る手間を減らしたい人
- 複数の物件や引っ越し条件を、費用面から比較したい人

自分自身が感じた「まずは費用感だけ知りたい」という課題を出発点にしています。

### 4-2. 利用の流れ

1. 会員登録なしで、予算・費用の種類・金額・状態を入力する
2. 必要に応じて参考概算を使い、費用合計・内訳グラフ・予算との差を確認する
3. 結果画面でリスト名や判断メモを入力する
4. 新規会員登録時にゲストの入力内容を引き継いで保存する、またはログイン済みの状態で結果を保存する
5. マイページから保存済みリストを開き、金額や状態、判断メモを更新する
6. 複数のリストを保存した場合は、2件を選択して費用を比較する

見積もり取得や家具家電の購入など、準備が進むたびに金額を更新し、検討を続けられる使い方を想定しています。

## 5. 既存サービスとの違い

比較対象として、[SUUMO引越し見積もり比較サイト](https://hikkoshi.suumo.jp/mitsumori/)を調査しました。

一括見積もりサービスは、複数の引っ越し業者へ見積もりを依頼し、料金やサービス内容を比較する際に便利です。

本サービスでは、ユーザーが集めた費用情報や参考概算を、賃貸初期費用・家具家電費用なども含めて保存・管理します。アプリから業者への見積もり依頼は行わず、依頼前の予算整理から、見積もり取得後の金額更新まで利用できます。

**引っ越し全体の費用を自分で整理し、予算判断や物件ごとの比較に使えること**を特徴としています。

---

## 6. このサービスで提供したい価値

- 引っ越しにかかる複数の出費を、カテゴリごとにまとめて管理できる
- 未確認・概算・確定を区別し、確認が進んだら金額や状態を更新できる
- 入力済みの費用合計と予算との差を把握できる
- 金額が大きいカテゴリを、内訳やグラフから確認できる
- 物件や引っ越し条件ごとにリストを保存し、2件の費用を比較できる
- 次に確認したいことや判断の理由を、メモとして残せる

**費用を整理・保存・更新しながら、物件契約や見積もり依頼の前後に予算判断をしやすくすること**を目指しています。

## 7. 実装済みの機能

以下は、現在のリポジトリで実装されている機能です。

### 7-1. 会員登録・ログイン・アカウント管理

- 名前・メールアドレス・パスワードによる会員登録
- メールアドレスとパスワードによるログイン・ログアウト
- Googleアカウントによる新規登録・ログイン
- メールによるパスワード再設定
- 現在のパスワードを確認したうえでのメールアドレス変更
- 退会時のユーザー情報・Google連携情報・費用リスト・費用項目の削除

Googleログインのみで登録したユーザーは、アプリ内のメールアドレス変更とパスワード再設定の対象外です。

### 7-2. ゲスト利用・入力内容の保存

- 会員登録なしで費用を入力し、計算結果を確認できる
- ゲストの入力内容をセッションに一時保持する
- メールアドレスまたはGoogleによる新規登録時に、ゲストの入力内容を引き継いで保存する
- ログイン済みの場合は、結果画面から費用リストを保存できる
- 保存時にリスト名を指定でき、未入力の場合は「引っ越し費用リスト」として保存する

既存アカウントへのログイン時は、ゲスト入力の自動保存は行いません。

### 7-3. 費用項目の入力・編集・削除

カテゴリごとに入力欄を追加・削除でき、費用名は候補からの選択と自由入力に対応しています。

| カテゴリ | 費用名の候補例 |
| --- | --- |
| 賃貸初期費用 | 家賃、敷金、礼金、仲介手数料、前家賃、火災保険料 |
| 引っ越し業者費用 | 引っ越し業者費用、その他引っ越し費用 |
| 家具家電費用 | 洗濯機、冷蔵庫、テレビ、電子レンジ、炊飯器、掃除機 |
| その他費用 | 交通費、手続き費用、雑費 |

金額は0円以上の整数で入力でき、空欄のまま保存することもできます。

### 7-4. 費用ステータスの管理

各費用項目に、次の状態を設定できます。

| 状態 | 用途 |
| --- | --- |
| 未確認 | まだ金額を確認できていない項目を残す |
| 概算 | 自分で入力した仮の金額や、参考概算を使って整理する |
| 確定 | 見積もりなどで確認した金額を管理する |

保存済みリストの編集画面で状態を変更できるほか、詳細画面の内訳に表示される項目は、その場で状態を更新できます。

### 7-5. 参考概算の入力補助

状態を「概算」にした際、対応する費用名について参考金額の入力を補助します。

- 賃貸初期費用：家賃以外の候補項目では、入力済みの家賃1か月分を仮の金額として使用する
- 家具家電費用：洗濯機・冷蔵庫など、費用名ごとに設定した固定値を使用する
- その他の対応項目：カテゴリに設定した固定値を使用する
- 候補にない費用名：自動入力せず、金額の手入力を案内する

これらはアプリ側で設定した仮の金額です。実際の物件条件や購入価格を保証するものではなく、確認後にユーザーが上書きできます。

### 7-6. 道路距離に基づく引っ越し業者費用の概算

費用名が「引っ越し業者費用」で、状態が「概算」の場合に利用できます。

- 出発地・到着地の郵便番号または住所を入力する
- Google Routes APIで自動車移動の道路距離を取得する
- 取得した距離をアプリ側の料金区分に当てはめ、参考金額を入力する
- 道路距離を画面に表示する
- 未入力・郵便番号の形式不正・経路なし・タイムアウト・API利用不可などに応じたメッセージを表示する

現在の料金区分は次のとおりです。

| 道路距離 | 参考金額 |
| --- | ---: |
| 50km未満 | 30,000円 |
| 50km以上200km未満 | 50,000円 |
| 200km以上500km未満 | 100,000円 |
| 500km以上 | 150,000円 |

料金はGoogleや引っ越し業者から取得する見積もりではなく、[アプリ独自の計算ロジック](app/services/moving_estimate_calculator.rb)による参考概算です。荷物量・繁忙期・業者ごとの料金体系などは反映していません。

郵便番号のみを入力した場合は、該当地域付近を基準とした参考距離になります。

### 7-7. 総額・内訳・予算比較・グラフ表示

- 入力された金額の合計を表示する
- 4カテゴリごとに費用を集計し、金額がある項目の内訳を表示する
- Chart.jsによる円グラフで、カテゴリごとの費用割合を表示する
- 概算項目を含むグラフには、金額更新により内訳が変わる可能性を案内する
- 予算入力時に、残額または超過額を表示する
- 予算超過時に、未確認項目・概算項目の有無に応じて確認を促す
- 予算超過時に、合計金額が最も大きいカテゴリを表示する

集計では、ステータスにかかわらず入力された金額を合計します。金額が空欄の項目は、計算上0円として扱います。

### 7-8. 複数リストの管理・2件比較・判断メモ

- 費用リストを複数保存し、マイページで一覧表示する
- 保存済みリストの名前変更・費用編集・削除を行う
- 2件を選び、費用合計・予算・予算との差・カテゴリ別合計を比較する
- どちらがいくら安いかを表示する
- 結果画面で判断メモを入力し、保存後も詳細画面から更新する

比較できるリストは、自分が保存した2件です。

### 7-9. その他の画面・UI

- 使い方・利用規約・プライバシーポリシーの表示
- Bootstrapを使った、画面幅に応じたフォーム・ボタン・比較表のレイアウト
- 費用入力欄の動的な追加・削除
- 費用フォームでのEnterキーによる意図しない送信の防止

## 8. 現在の制約と対応

### 8-1. 参考概算と実際の金額には差がある

距離から算出する業者費用や、固定値を使用する費用は、予算整理のための参考情報です。画面上で参考概算であることを伝え、確認後は金額と状態を更新できるようにしています。

道路距離の取得にはGoogle Routes APIの設定が必要です。APIで距離を取得できない場合はエラーを表示し、金額を手入力して費用管理を続けられます。

### 8-2. 金額が空欄でも合計・予算判定が表示される

金額が空欄の項目は計算上0円のため、表示された合計が引っ越し全体の最終的な総額とは限りません。未確認項目が残っている場合は、予算内の表示でも追加費用が発生する可能性があります。

現在、結果画面の費用内訳には金額が0円より大きい項目を表示しています。空欄や0円の項目の確認・編集は、費用編集画面で行います。未確認項目だけをまとめた専用一覧や絞り込みは未実装です。

### 8-3. ゲストの再計算では入力内容をフォームに復元しない

ゲストの結果画面にある「もう一度計算する」は、新しい入力フォームを開く動作です。直前の入力内容をフォームへ復元する機能は未実装です。

保存済みリストは編集画面から既存の入力内容を変更できます。

### 8-4. 比較できる件数と項目に制限がある

現在は2件の費用リストについて、総額・予算・カテゴリ別合計を比較します。費用項目ごとの差分や、未確認項目の比較は未実装です。

| データベース | PostgreSQL | ユーザー・費用リスト・費用項目・認証情報の保存 |

| JavaScriptビルド | esbuild | JavaScriptのバンドル |
| 外部API | Google Routes API | 出発地・到着地間の道路距離取得 |
| メール送信 | Action Mailer、Resend | パスワード再設定メールの送信 |
| 開発環境 | Docker、Docker Compose | Rails・PostgreSQLの開発環境 |
| デプロイ先 | Render | アプリケーションの公開 |

| CI・静的解析 | GitHub Actions、RuboCop、Brakeman | RSpecの実行、コードスタイル・セキュリティの検査 |

バージョンは `.ruby-version`・`Gemfile.lock`・`package.json` の記載をもとにしています。

### 実装上の工夫

- 費用のカテゴリと状態をenumで管理し、表示や集計に利用しています。
- 費用リストと費用項目をネストしたフォームでまとめて保存・更新できるようにしています。
- 保存済みリストは `current_user.cost_lists` から取得し、他のユーザーのリストを操作できないようにしています。
- 道路距離を取得する処理と、距離から参考金額を決める処理をサービスクラスに分けています。
- 外部APIの入力チェックやエラー処理、距離による料金区分、認証・費用管理などのテストを用意しています。

### テスト・静的解析の実行コマンド

```bash
# RSpec
docker compose exec web bundle exec rspec

# JavaScriptのテスト
docker compose exec web yarn test:javascript

# コードスタイル
docker compose exec web bin/rubocop

# セキュリティの静的解析
docker compose exec web bin/brakeman --no-pager
```

現在のGitHub Actionsでは、RSpec・RuboCop・Brakemanを実行します。JavaScriptのテストは個別のコマンドで実行できます。
